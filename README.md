# Т1 Дата-агент

Учебное веб-приложение для проверяемого анализа данных из нескольких источников. Пользователь задаёт вопрос в чате, видит таблицу, график и трассировку, сохраняет отчёт и выгружает его в CSV, XLSX или PDF. Отдельная страница позволяет собирать дашборды с фильтрами.

## Быстрый запуск

Требуется Python 3.11+.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
# Заполните YC_FOLDER_ID и YC_API_KEY в .env
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. Ключ и идентификатор каталога считываются только из переменных окружения или локального `.env`, который включён в `.gitignore`. Для Yandex AI Studio используется совместимый Chat Completions API. Модель по умолчанию — `yandexgpt-lite`; её можно заменить через `LLM_MODEL`. Базовый URL задаётся `LLM_BASE_URL`.

## Данные

Основной источник — [синтетический банковский портфель](https://github.com/ZDari0102/T1_AI_analyst/tree/main/kubgu-bank-data) (`data/bank_portfolio.xlsx`, 756 строк, 10 полей). При первом запуске файл импортируется в локальную SQLite `.runtime/portfolio.sqlite3`; исходный XLSX агент не изменяет. Таблица `positions` содержит 12 месячных срезов и 2 дополнительных дневных среза. Для месячной динамики используются только строки `snapshot_kind='MONTH_END'`. Проверочное значение: сумма активов на 31.10.2026 равна 1 022 303 980,96 ₽.

В репозитории также сохранён прежний `bank_data.db` и набор из 20 вопросов. Он описывает **другую схему** (`balance_sheet`) и даты на начало месяца, поэтому его эталоны нельзя напрямую применять к `bank_portfolio.xlsx`. Текущий прототип использует XLSX из указанного пользователем репозитория; вопросы для него следует формулировать по схеме `positions`.

### Другие источники

В разделе **Источники данных** можно добавить несколько баз SQLite (`.db`, `.sqlite`, `.sqlite3`), таблиц из CSV/XLSX и подключений PostgreSQL. Для SQLite можно выбрать таблицу. Загруженные файлы сохраняются в `.runtime/sources`, подключения и выбранные таблицы — в `.runtime/state.sqlite3`. Эти данные исключены из Git. Максимальный размер файла — 30 МБ; для CSV требуется UTF-8. Для PostgreSQL нужен доступный сервер и пользователь с правом чтения; URL подключения сохраняется локально в `.runtime/state.sqlite3`. Для него устанавливается `psycopg[binary]` из `requirements.txt`.

При создании диалога выберите источник над полем вопроса. Каждый диалог закреплён за своим источником. Для новых схем агент получает реальные поля и пример записей; специальная банковская логика используется только для исходного учебного портфеля. SQL-инструмент принимает только один SELECT/WITH, для SQLite ограничивает чтение выбранной таблицей, для PostgreSQL использует соединение с режимом только чтения и тайм-аутом. Для PostgreSQL дополнительно выдайте учётной записи права только на нужные таблицы.

В разделе **Дашборды** выберите источник, показатель, операцию, разрез и вид графика. Можно добавить до шести фильтров по значениям полей и период по полю даты. После построения видны карточки показателей, график и таблица; конфигурацию можно сохранить и открыть снова. Числа рассчитываются запросами к выбранному источнику. Если запущен Apache Superset, его интерактивный BI-дашборд также отображается на этой странице.
Для учебного банковского портфеля по умолчанию выбираются только месячные срезы; карточка динамики показывает значение последнего периода.

## Apache Superset (локальный Docker)

Superset работает в отдельном контейнере на `http://127.0.0.1:8088`. Данные для него копируются из учебной SQLite в PostgreSQL; Superset подключается пользователем `portfolio_reader` с правами только на чтение. Контейнеры доступны только на `127.0.0.1`. Это локальная демонстрационная конфигурация, не предназначенная для открытого интернет-хостинга.

При первом запуске скрипт создаст локальный `.env.superset` со случайными паролями. Файл включён в `.gitignore` и `.dockerignore`. Если он уже создан, скрипт сохранит его: смена пароля PostgreSQL в существующем томе требует отдельного обновления роли.

```powershell
python scripts/init_superset_env.py
docker compose --env-file .env.superset -f compose.superset.yml up -d --build
python scripts/load_portfolio_pg.py
python scripts/setup_superset.py
python -m scripts.register_portfolio_source
python -m uvicorn app:app --host 127.0.0.1 --port 8765
```

Дождитесь готовности Superset по `http://127.0.0.1:8088/health` перед запуском `setup_superset.py`. Скрипт создаёт источник, набор данных, два графика и дашборд; повторный запуск обновляет их. Встроенный просмотр использует короткоживущий гостевой токен через сервер приложения. Для входа в полный интерфейс Superset используйте имя и пароль из локального `.env.superset`. Браузеру нужен доступ к `https://esm.sh` для загрузки официального SDK встраивания. Если SDK недоступен, в приложении остаётся ссылка «Открыть Superset».

## Архитектура

Оркестратор выполняет ограниченный цикл из максимум двенадцати шагов с одной попыткой исправить SQL после проверки:

1. **Бизнес-аналитик** определяет метрику, период, фильтры и необходимость уточнения.
2. **Инженер данных** проверяет подключённый источник, записи и дефекты.
3. **Аналитик данных** составляет SQL по схеме и карточке данных.
4. **SQL-инструмент** выполняет запрос в SQLite с правами только на чтение.
5. **BI-разработчик** выбирает таблицу и график.
6. **Тестировщик** проверяет наличие результата, соответствие полей графика, метрику, группировку и фильтры.

Оркестратор фиксирует действия, SQL, формулу, время и расход токенов в трассировке. Ответы и отчёты хранятся в `.runtime/state.sqlite3` между сессиями. LLM интерпретирует задачу и предлагает SQL, а числовые значения вычисляет только SQLite. При отказе или недоступности LLM приложение показывает ошибку, не подставляя вымышленные данные.

Безопасность SQL обеспечивают три слоя: соединение `mode=ro&immutable=1`, SQLite authorizer с разрешением чтения только таблицы `positions` и белого списка функций, а также лимиты времени и числа строк. Несколько SQL-инструкций и операции изменения данных отклоняются. Произвольный код из ответа LLM не исполняется.

## Возможности интерфейса

- Чат с историей и уточняющими вопросами.
- Удаление диалога вместе с сообщениями и журналом; сохранённые отчёты остаются.
- Профиль источника: структура, типы, пропуски, повторные ключи, даты и первые записи.
- Редактируемая карточка полей с описанием, единицами и формулами.
- Таблица, график, фильтры, период, единицы и раскрываемая трассировка.
- Несколько подключённых источников и настраиваемые дашборды с сохранением.
- Сохранённые отчёты и выгрузка CSV, XLSX и PDF.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

Проверяются профиль данных, эталонная сумма, независимость загруженных источников, фильтры и блокирование опасных SQL. Для полноценной демонстрации чата нужна действующая LLM и доступ к её API. Подключение PostgreSQL требует доступного сервера и не покрыто локальным интеграционным тестом. Приложение рассчитано на локальный учебный контур; многопользовательская авторизация не реализована.
