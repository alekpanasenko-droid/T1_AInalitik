# Т1 Дата-агент

Учебное веб-приложение для анализа данных и финансового моделирования. В чате можно задать вопрос обычным языком, получить таблицу и график, проверить формулы и SQL, сохранить отчёт и выгрузить его в CSV, XLSX или PDF.

## Быстрый запуск

Требуется **Python 3.13 или новее**. Команды ниже рассчитаны на PowerShell. Выполните их из корня репозитория.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Для вопросов в свободной форме заполните `YC_FOLDER_ID` и `YC_API_KEY` в локальном `.env`. Настройки модели и URL API описаны в [шаблоне окружения](.env.example). Дашборды и кнопка **«Учебный пример»** работают без ключа. Локальные ключи, пароли и данные в `.runtime/` исключены из Git.

## Источники и дашборды

При первом запуске [синтетический банковский портфель](https://github.com/ZDari0102/T1_AI_analyst/tree/main/kubgu-bank-data) импортируется из `data/bank_portfolio.xlsx` в `.runtime/portfolio.sqlite3`. В таблице `positions` 756 строк, 10 полей, 12 месячных срезов и 2 дневных. В помесячных расчётах выбираются только срезы `MONTH_END`. Файл `bank_data.db` хранит прежний набор с таблицей `balance_sheet`.

В **«Источниках данных»** можно подключить несколько файлов SQLite, CSV, XLSX и баз PostgreSQL, выбрать таблицу и проверить её структуру. Размер загружаемого файла ограничен 30 МБ. CSV нужен в UTF-8. Выберите источник над полем ввода перед созданием диалога. В **«Карточке данных»** можно уточнять описания полей, единицы и формулы.

В **«Дашбордах»** выбираются показатель, операция, период, разрез, график и до шести фильтров. Отчёты, история диалогов и настройки сохраняются локально. Удаление диалога сохраняет уже созданные отчёты.

## Финансовое моделирование

В режиме **«Моделирование»** введите горизонт до 60 месяцев, валюту, деньги на счёте до запуска, стартовые инвестиции, ежемесячную выручку и расходы, отсрочку оплаты покупателей и срок амортизации. Для NPV нужна эффективная годовая ставка дисконтирования. Агент уточняет недостающие параметры и запоминает вводные и сценарии в диалоге.

Модель оценивает операционную прибыль, поступления, остаток денег, потребность в финансировании, NPV, IRR и простую окупаемость. Она сравнивает сценарии, проверяет чувствительность к изменениям вводных, рассчитывает безубыточность и минимальный аванс. Поступления за пределами горизонта выводятся отдельно. Расчёт выполняется на конец месяца, с линейной амортизацией, без налогов, кредитов, процентов и остаточной стоимости.

## Apache Superset

Superset и PostgreSQL запускаются локально через Docker Compose. Подготовьте Python-окружение по инструкции выше. Затем выполните команды из корня репозитория.

```powershell
python -c "from agent.store import initialize; initialize()"
python scripts/init_superset_env.py
docker compose --env-file .env.superset -f compose.superset.yml up -d --build
```

Когда [проверка готовности Superset](http://127.0.0.1:8088/health) вернёт `OK`, загрузите данные и настройте оба дашборда.

```powershell
python scripts/load_portfolio_pg.py
python scripts/setup_superset.py
python -m scripts.setup_modeling_superset
```

- Банковский дашборд с шестью графиками доступен в разделе **«Дашборды»** приложения.
- Для модели нажмите **«Сохранить отчёт»**, откройте его в разделе **«Отчёты»** и нажмите **«Показать в Superset»**. Встроенный дашборд показывает строки выбранного отчёта и позволяет фильтровать графики по сценарию.
- Чтобы использовать копию учебного портфеля из PostgreSQL как источник чата, выполните `python -m scripts.register_portfolio_source`.

Superset доступен на [http://127.0.0.1:8088](http://127.0.0.1:8088). Учётные данные создаются в локальном `.env.superset`. Для встраивания дашбордов браузеру нужен доступ к `esm.sh`. Конфигурация рассчитана на локальную демонстрацию.

## Архитектура

Оркестратор координирует бизнес-аналитика, инженера данных, аналитика данных, BI-разработчика и тестировщика. Шаги, вызовы инструментов, формулы и время выполнения видны в трассировке.

- **Анализ** использует SQL только для чтения. В SQLite чтение ограничено выбранной таблицей и разрешёнными функциями. Для PostgreSQL используется соединение в режиме чтения с ограничением времени.
- **Моделирование** преобразует вводные в проверяемые параметры. Python выполняет расчёт, а `numpy-financial` используется для NPV и IRR. Браузер отображает результат в чате, сохранённые помесячные отчёты можно открыть в Superset.

## Автоматическая проверка

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют контрольные значения портфеля и модели, изоляцию источников, ограничения SQL, сохранение контекста модели и экспорт отчёта.
